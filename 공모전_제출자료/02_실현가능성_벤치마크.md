> 2026-09-13 주석: 아래 수치는 기존 합성 개발 샘플의 기록이며 이번에 실행 로그 확인·재측정하지 않았다. 현업 정확도나 독립 평가 결과가 아니다. 누락 정답의 업무상 필수 여부도 현업 검토가 필요하다.

## 2. 실측 벤치마크 — 현실적 샘플 문서

### 입력: 이기종 4문서 (△△ 폐수처리시설 이송펌프 패키지)
| 문서 | 형식 | 발행 | 언어 |
|---|---|---|---|
| 기계장비 사양서 | **PDF** | 기계설계팀 | 한글 |
| 전기 부하계산서 | **CSV(표)** | 전기팀 | 영문 |
| 전기 단선결선도 주석 | **TXT** | 전기팀 | 영문 |
| 설비 목록 | **CSV(표)** | 프로젝트 | 한/영 혼용 |

### 정답셋: 의도적으로 주입한 불일치 5건
| # | 설비 | 항목 | 내용 | 유형 |
|---|---|---|---|---|
| 1 | P-101 | 정격출력 | 사양서·계산서·목록 15 kW / **도면 18.5 kW** | 도면 오기재 |
| 2 | P-101 | 정격전압 | 사양서·계산서·목록 380 V / **도면 440 V** | 도면 오기재 |
| 3 | P-101 | 케이블 규격 | 계산서·도면 25 mm² / **설비목록 35 mm²** | 설비목록 미갱신 |
| 4 | M-101 | 모델명 | 사양서 **SM-132M** / 설비목록 **SM-132S** | 한 글자 차이(프레임 상이) |
| 5 | P-102 | 양정 | 사양서에만 기재, 나머지 3문서 누락 | 예비설비 사양 누락 |

### 결과

| | 1차 실행 (수정 전) | 2차 실행 (정규화 2건 수정 후) |
|---|---|---|
| 탐지된 이슈 | 9건 | **5건** |
| 정답 탐지 (Recall) | 5/5 | **5/5 (100%)** |
| 오탐 (False Positive) | 4건 | **0건** |
| 정밀도 (Precision) | 5/9 ≈ 56% | **5/5 (100%)** |

### 1차 실행에서 발견한 문제 → 수정 (엔지니어링 성숙도의 근거)
| 오탐 원인 | 수정 |
|---|---|
| 사양서 PDF의 "120 m³/h"(위첨자)와 CSV의 "120 m3/h"를 **다른 단위**로 인식 | 단위 유니코드 정규화 함수 `normalize_unit()` 추가 (m³→m3, SQMM→mm², ℃→C 등) |
| 도면의 케이블 "4C x 25 SQMM"를 값 25로 못 뽑고 **문자열 전체로 비교** | 심선 수 접두어 제거 + 단면적만 추출하는 `clean_cable_value()` + 추출 프롬프트 보강 |

> 이 두 수정으로 **오탐 4건 → 0건**. "돌려보고, 문제를 찾고, 고쳤다"는 과정 자체가 구체성·실현가능성의 증거.

### AI 추출 성과 (수동 대비)
- 형식이 다른 4개 문서에서 설비 3대(P-101·P-102·M-101)를 자동 식별
- **한글 "정격출력" = 영문 "RATED OUTPUT" = 표 헤더 "Power(kW)" = "정격출력(kW)"** → 한 항목으로 통합
- 한글 "원심펌프" = 영문 "TRANSFER PUMP" → Pump로 정규화 → 누락 검사 동작
- 부가값(정격전류 FLC, 역률, 효율, 주파수)도 함께 추출

## 3. 운영 로드맵 (솔직한 단계별 필요사항)

### 현재 (MVP / 데모)
- ✅ 텍스트 레이어 있는 PDF·Excel·CSV·TXT·이미지
- ✅ 파라미터·단위·설비유형 정규화 사전 (한/영)
- ✅ 검토 상태(의도된 차이/조치 필요) + 예외 사유 기록 + PDF 리포트
- ⚠️ 단일 사용자, 인메모리 DB(SQLite), 계정 없음

### 파일럿 (사내 실제 프로젝트 1~2건)
- 실제 프로젝트 정답셋 구축 → 공종별 Recall/Precision 측정·리포트
- 현장 용어에 맞춘 파라미터·단위 사전 확장 (프로젝트별 커스터마이즈)
- **스캔 도면 OCR 품질 검증** (현재 vision 추출의 한계 구간)
- 벤더 데이터시트 다양한 양식 대응

### 운영 (사내 표준 검토 툴)
- 계정·권한·감사 로그(누가 언제 무엇을 검토했는가 불변 기록)
- 문서 버전(Rev) 관리 — "도면 Rev.C를 검토했다"는 이력
- CAD/BIM 파서 추가 (같은 엔진, 파서만 확장)
- 검토 워크플로우(이슈 배정·승인 라우팅·알림)
- 사내 EDMS / PLM 연동

## 4. 한계와 대응 (질문 대비)

| 예상 질문 | 답변 |
|---|---|
| "AI가 값을 잘못 읽으면?" | 모든 값에 원문 위치·문장을 첨부해 엔지니어가 즉시 대조. 판정은 결정론 코드라 값이 틀려도 "다르다/같다"는 재현 가능 |
| "스캔 도면·손글씨는?" | 현재 한계 구간. 파일럿에서 OCR 품질 측정 후 대응 결정 (정직하게) |
| "왜 검토만, 계산·설계는?" | 계산은 ETAP·모델링은 BIM이 있음. 기존 정합성 도구가 있다. 통합 시스템 밖 문서 검토에 남는 수요를 확인할 계획 |
| "규칙엔진으로 되지 않나?" | 사전 매핑도 표기를 연결할 수 있다. 다양한 양식에 대한 추출·매핑 준비 비용을 LLM이 줄이는지 검증 필요 |
