# 배포 체크리스트 — Vercel 프론트 + 백엔드 연결 (약 15분)

> 이 문서는 **대시보드에서 직접 클릭해야 하는 작업**만 남기고, 코드/설정 준비는 이미 끝낸 상태에서 시작합니다.
> (백엔드는 이미 환경변수 기반으로 작성되어 있고, `render.yaml`도 저장소 루트에 추가해 뒀습니다.)

완료 기준: **Vercel 배포 URL에 로그인 없이 들어가서 "데모 프로젝트 불러오기"를 눌렀을 때 대시보드가 뜨는 것.**

---

## 1단계 — 백엔드를 Render에 배포 (5분)

1. https://render.com 접속 → GitHub 계정으로 로그인 (가입 무료, 카드 등록 불필요)
2. **New +** → **Blueprint** 선택
3. 저장소 `Acorn00002/Himec-` 선택 → Render가 루트의 `render.yaml`을 자동으로 읽어서 `crosscheck-backend` 서비스를 구성함
4. 배포 전 환경변수 입력 화면에서:
   - **`GEMINI_API_KEY`** → 로컬 `.env` 파일에 있는 값을 그대로 복사해서 붙여넣기 (이 값은 `render.yaml`에 없음 — 코드/깃허브에 올라가지 않은 비밀값이라 여기서 직접 입력해야 함)
5. **Apply** → 배포 시작 (2~5분 소요, 로그에 `Uvicorn running on http://0.0.0.0:$PORT` 뜨면 완료)
6. 배포 완료 후 나오는 URL 복사 — 예: `https://crosscheck-backend-xxxx.onrender.com`
7. 브라우저로 `https://<그 URL>/api/health` 접속해서 `{"status":"ok"}` 뜨는지 확인

**참고:** 무료 플랜은 15분간 요청이 없으면 서버가 잠들고, 다음 요청 시 깨어나는 데 30~50초 걸립니다(콜드 스타트). 발표 직전에 한 번 접속해서 미리 깨워두세요.

---

## 2단계 — Vercel에 백엔드 주소 연결 (3분)

1. https://vercel.com 대시보드 → 프로젝트(`himecproject`) 선택
2. **Settings → Environment Variables**
3. 추가:
   | Key | Value |
   |---|---|
   | `NEXT_PUBLIC_API_URL` | 1단계에서 복사한 Render 주소 (끝에 `/` 없이, 예: `https://crosscheck-backend-xxxx.onrender.com`) |
4. **Save**
5. **Deployments** 탭 → 가장 최근 배포 옆 **⋯ → Redeploy** (환경변수는 재배포해야 반영됨)

---

## 3단계 — 백엔드가 Vercel 프론트를 허용하도록 CORS 갱신 (2분)

1. Render 대시보드 → `crosscheck-backend` 서비스 → **Environment**
2. `CORS_ORIGINS` 값을 아래처럼 **콤마로 이어서** 수정:
   ```
   http://localhost:3000,https://himecproject.vercel.app
   ```
   (실제 프로덕션 도메인은 Vercel 프로젝트 상단에 표시된 주소로 — `-git-main-...` 붙은 프리뷰 주소 말고 **프로덕션 도메인**)
3. 저장하면 자동 재배포됨

---

## 4단계 — Vercel 로그인 보호벽 해제 (1분, 가장 중요)

지금 상태로는 외부인이 링크를 눌러도 `vercel.com/login`으로 튕깁니다.

1. Vercel 프로젝트 → **Settings → Deployment Protection**
2. **Vercel Authentication** 을 **Disabled** 로 변경 (또는 "Only Preview Deployments"로 좁히고, 제출 링크는 **프로덕션 URL**만 사용)
3. Save

---

## 5단계 — 최종 검증 (3분)

시크릿/게스트 브라우저 창(로그인 안 된 상태)으로:

1. `https://<프로덕션 도메인>.vercel.app` 접속 → 로그인 창 없이 랜딩 페이지가 바로 뜨는지 확인
2. **데모 프로젝트 불러오기** 클릭 → 대시보드에 이슈 6건이 뜨는지 확인
3. (선택) **새 프로젝트** → `데모_샘플문서/`의 4개 파일 업로드 → 교차검증 실행까지 실제로 동작하는지 확인
   - 첫 요청은 Render 콜드 스타트로 느릴 수 있음 → 발표 5분 전에 미리 한 번 열어서 깨워두기

**여기까지 되면 제출 링크 하나로 심사위원이 바로 써볼 수 있는 상태입니다.**
